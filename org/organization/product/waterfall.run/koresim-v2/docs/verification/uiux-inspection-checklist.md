# UI/UX 점검 리스트 (실 브라우저 e2e 기반)

- 방법: 격리 로컬 인스턴스(`scripts/run_local_upstage_e2e.py`, 포트 8099)를 실 브라우저로 순회하며
  화면별로 폰트 크기 분포, 입력 필드/라벨, 탭 타깃, 색 대비, 가로 오버플로우를 실측.
- 점검 화면: 랜딩(`/`), 대시보드(`/app`), 새 프로젝트 모달, 프로젝트 상세(`/projects/{id}`),
  유형 선택(`/type`), 인테이크(`/intake`), 로딩(`/loading`), 결과(`/results`).
- 뷰포트: 데스크톱 1280px, 모바일 390px.
- 심각도: **S1 치명**(사용 불가/데이터 오독) · **S2 주요**(가독성·접근성 저해) · **S3 경미**(일관성·완성도) · **S4 nit**.
- 측정 근거는 각 항목에 인라인 표기(예: 대비 3.38:1, 폰트 17종). 재점검 방법은 문서 하단 참고.

---

## A. 반응형(모바일 390px) — 가장 시급

- [x] **S1 · 결과 상단 툴바가 모바일에서 겹침/잘림.** (수정됨 — `@media(max-width:640px)`에서 `.results-toolbar .wrap`를 `height:auto`+`flex-wrap:wrap`로, 두 그룹 세로 스택. 데스크톱 52px 단일행 유지.) 결과 페이지 툴바(`.results-toolbar .wrap`, w=433px)가
  390px를 넘어 프로젝트명("시니어 돌봄 스피커 (UI e2e) 2026. 7. 11.")과 우측 버튼("＋ 새 시뮬레이션", "⌁ 내보내기")이
  서로 겹쳐 렌더됨. 데스크톱(1280px)에서는 정상(좌 right=811, 우 left=885, 여백 74px).
  → 좁은 폭에서 `flex-wrap`/세로 스택 또는 액션을 오버플로우 메뉴로.
- [ ] **S1 · 상단 진행 레일(1 프로젝트 · 2 유형 선택 · 3 입력 · 4 결과)이 모바일에서 우측 잘림.** `span.active` right=413px(>390).
  마지막 "4 결과" 라벨이 화면 밖으로 나감 → 가로 스크롤/축약 라벨/아이콘화 필요.
- [x] **S2 · 결과 판정 헤드라인(H1)이 모바일에서 과대.** (수정됨 — `fontSize:38 → clamp(24px,6.2vw,38px)`. 390px에서 24.18px≈4줄, 데스크톱 38px 유지.) 38px 고정으로 헤드라인이 약 9줄로 화면 한 판을 차지하던 문제.
- [ ] **S2 · 결과 표(고정 그리드)의 모바일 대응 확인.** 기회/리스크 맵 `92px repeat(5,1fr) 1.6fr`, 거부요인 라벨 고정 `width:230px`,
  ROI/연령 전체표 등 고정 컬럼 그리드가 좁은 폭에서 압착됨 → 소폭에서 카드형/가로 스크롤 래퍼로 폴백.
- [ ] **S3 · 프로젝트 배지·보고서 메타 겹침.** 결과 상단 "🗀 프로젝트명 · 완료" 고스트 텍스트와 "크리에이티브 비교 분석 보고서"가
  모바일에서 겹쳐 보임 → 간격/줄바꿈 정리.
- [ ] **S3 · 전역 상단 내비(`div.wrap.row`)가 모바일에서 right=433px.** 로고+제품/프로젝트/Classic이 폭 초과. 접힘/햄버거 검토.

## B. 타이포그래피(폰트 크기)

- [ ] **S2 · 타입 스케일 파편화(결과 페이지 폰트 17종).** 실측 distinct 크기: 10, 10.5, 11, 11.5, 12, 12.5, 13, 13.5, 14, 14.5, 15, 16, 17, 18, 24, 26, 38px.
  0.5px 단위(10.5/11.5/12.5/13.5/14.5)가 섞여 위계가 흐릿함 → 6~8단계 토큰(예: 11/12/13/14/16/20/26/38)으로 수렴, 인라인 `fontSize` 하드코딩 축소.
- [ ] **S2 · 10px 초소형 텍스트.** 진행 레일 번호(1~4)와 일부 라벨이 10px. 본문성 텍스트 최소 12px 권장(모바일 12~13px).
- [ ] **S3 · 11px 라벨 남용.** `.lbl-mono`/`.faint`/`.lbl`가 11~11.5px로 광범위 사용(결과 페이지 11px 텍스트 264개소). 메타에 한정하고 12px로 상향 검토.
- [ ] **S3 · 인라인 스타일 폰트 하드코딩.** 컴포넌트 다수가 `style={{fontSize:…}}`로 직접 지정 → 유틸/토큰화로 일관성 확보(회귀 방지).

## C. 중복 입력 / 정보 재요청

- [ ] **S2 · 프로젝트 이름·설명 이중 입력.** 새 프로젝트 모달에서 "프로젝트 이름/한 줄 설명"을 받고,
  프로젝트 상세 정보 폼에서 다시 "이름/설명" 필드를 노출 → 상세 폼에서는 인라인 편집/읽기전용 표시로 중복 완화.
- [ ] **S2 · 프로젝트 컨텍스트 ↔ 인테이크 재질문 중복.** 프로젝트 상세에 이미 "제품 컨텍스트/기능/가격/타겟 메모/대안"이 있는데,
  인테이크 대화가 "제품/핵심 고객/가장 큰 장점/톤"을 다시 물음. 프로젝트 값이 채워졌을 때 인테이크가 **선반영(prefill)하고 재질문을 생략**하는지 검증/보완.
  (관련: `withProjectDefaults(session, project, type)` 경로가 실제로 슬롯을 채우고 planner가 이를 존중하는지 확인.)
- [ ] **S3 · 타겟 표현 중복.** "타겟 메모"(프로젝트) 와 인테이크 "핵심 고객", 결과 필터가 각각 별도로 존재 → 단일 소스 후 파생 노출 검토.

## D. 접근성(A11y)

- [x] **S2 · 저대비 라벨(WCAG AA 미달).** (수정됨 — `--fg-faint #8C887F → #6B675E`, 실측 대비 **3.38 → 5.4:1** AA 통과. `.lbl-mono`/`.faint`/`.lbl` 등 전역 적용.)
- [ ] **S2 · 폼 입력 라벨 미연결.** 결과 페이지 후속질문/인터뷰/피드백 입력 5개가 `<label for>`/`aria-label` 없이 placeholder·주변 텍스트에 의존(noLabel=5).
  랜딩 히어로 입력도 라벨 없음(noLabel=1) → 접근 가능한 이름 부여.
- [ ] **S3 · 탭 타깃 < 44px.** 상단 내비 버튼 24px 높이, 선택 칩("전체/C 선택/C 미선택") 27px 등. 모바일 최소 44×44px 권장.
- [ ] **S3 · 색만으로 정보 전달 점검.** 안별 색상(A/B/C/D)·기회=채움/리스크=테두리 등은 라벨/기호 병기가 되어 있으나, 신규 뷰 추가 시 색 단독 인코딩 금지 원칙 유지.

## E. 일관성 & 마이크로카피

- [ ] **S3 · 화면 제목 표현 혼재.** H1이 화면별로 "대시보드 / 어떤 시뮬레이션으로 볼까요? / 입력값을 대화로 정리합니다 / 무엇을 시장에 물어볼까요?"로 어조·형식이 섞임 → 톤 가이드 정렬.
- [ ] **S3 · 결과 H1을 판정 헤드라인으로 사용.** 페르소나 발언형 문장이 문서 H1이 됨(SEO/스크린리더 맥락 약화) → 시각적 헤드라인은 유지하되 문서 구조상 H1은 "OO 분석 보고서" 등으로 분리 검토.
- [ ] **S4 · React Grab 개발 툴바가 배포 번들에 포함.** 접근성 트리에 "Select element/Open comments/Copy all comments/Disable React Grab" 노출 → 프로덕션 빌드에서 제외.
- [ ] **S4 · 숫자/단위 표기 일관성.** "%p", "±", "명", "≈ N억/년" 등 표기 규칙 문서화.

## F. 상태(로딩/빈/에러) — 추가 점검 필요

- [ ] **S3 · 빈 상태 카피.** 프로젝트 0개/실행 이력 0개/키워드 0개 등 빈 상태 문구·CTA 점검(실행 이력 없는 신규 프로젝트 화면).
- [ ] **S3 · 로딩 페이지 지속/전환.** `/loading`에서 진행률·예상 시간·취소 동작, 실패 시 재시도 경로 점검.
- [ ] **S3 · 결과 에러/부분결과.** run 실패·부분완료·표본 부족(<50) 시 경고 배너·해석 주의 문구 노출 확인.

## 재점검 방법

```bash
UPSTAGE_API_KEY=dummy LLM_BACKEND=fake uv run python scripts/run_local_upstage_e2e.py
# 브라우저로 http://127.0.0.1:8099/app 순회, 1280px/390px에서 각 화면 확인
```
- 폰트/대비/오버플로우 자동 수집 스니펫은 이 세션의 e2e 감사 스크립트(문서 이력) 참고.
- 우선순위: A(반응형) → D(접근성) → B(타이포) → C(중복입력) → E/F.
