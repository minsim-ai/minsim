현재 제품 흐름

README의 agent flow와 worker 구현을 합친 실제 실행 경로입니다.

1. 목표 입력 사용자가 가격, 캠페인, 문구, 출시 등 의사결정 목표를 자연어로 입력합니다.
2. Intake 정리 키워드 라우팅, slot 추출, 질문/폼/후보 생성, safe summary 작성.
3. Persona 실행 RQ worker가 50-200명 persona를 샘플링하고 LLMClient로 응답을 수집합니다.
4. 집계와 신뢰 레이어 metrics, segments, insights, parse quality, sample summary, raw result를 envelope로 저장.
5. 결과 Agent Analysis / Report / QA가 aggregate-only input으로 해석, 권고, 검수를 수행합니다.

Agent 경계

현재 구조의 핵심은 raw 데이터와 safe context를 분리하는 것입니다.

Intake

  • 목표 라우팅
  • slot 추출
  • 질문/폼 결정
  • safe summary 작성

Simulation

  • Persona sampling
  • Batch LLM calls
  • Partial progress
  • Metrics aggregation

Result Agents

  • Analysis
  • Report
  • QA
  • Fallback scaffold

Agent 입력 허용

metrics, segments, insights, quality, warnings, provider metadata, safe_intake_summary

기본 제외

raw_results, persona UUID/full rows, raw model responses, raw chat transcript, hidden prompts

앞으로 보완되어야 할 사항

문서상 남은 일과 코드상 scaffold/first slice로 남은 부분만 적었습니다.

Productization
PR/main release, auth polish, login-backed E2E

CLAUDE.md의 남은 작업. 데모 gate 이후 운영/릴리즈 품질을 올리는 항목입니다.

Protocol
Price Research V2 / Product QA renderer와 fixture 확장

React protocol-aware result, deterministic eval fixtures, report grounding fixture가 문서상 미완료입니다.

Observability
step metadata 강화

protocol step에 latency_ms, retry_count, fallback_used가 추가되어야 한다고 실행계획에 남아 있습니다.

Progress
SSE protocol step progress

raw prompt를 노출하지 않으면서 protocol 단계별 진행률을 표시하는 계약이 미완료입니다.

Policy
계정/조직/결제, 법무/데이터 보존 정책

V2 product features로 남아 있으며 실제 billing과 외부 패널 리크루팅은 현재 plan scope 밖입니다.

Validation
large local Ollama validation

`gemma3:27b`가 가능한 환경에서 local large-model 검증이 남아 있습니다.
